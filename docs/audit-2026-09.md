## P0 — broken in production

### 1. Both "Download CV" buttons serve an HTML page, not the PDF

`src/assets/usama-cv.pdf.asset.json` points at `/__l5e/assets-v1/f411044b-.../Usama-Munawar-CV.pdf` — a **Lovable-hosted** path. On Vercel that path matches no file, so the SPA rewrite in `vercel.json` serves `index.html`.

Verified against production:

```
curl -sI https://dev-usama-portfolio.vercel.app/__l5e/assets-v1/f411044b-f3f1-47e5-8204-dbc8bab11afa/Usama-Munawar-CV.pdf
→ 200  Content-Type: text/html; charset=utf-8
```

With `download="Usama-Munawar-CV.pdf"` on the anchor, a recruiter gets a 17 kB HTML file named `.pdf` that opens as garbage. Two call sites: `Hero.tsx:90`, `About.tsx:175`.

**Fix:** put the real PDF in `public/usama-munawar-cv.pdf`, link `/usama-munawar-cv.pdf`, delete the `.asset.json` import.

## P1 — performance and conversion

### 2. The 634 kB syntax highlighter is preloaded on every page

`vite.config.ts` names `syntax: ['react-syntax-highlighter']` in `manualChunks`. That promotes the chunk into the entry's preload set, so `dist/index.html` (and the live HTML) contains:

```html
<link rel="modulepreload" crossorigin href="/assets/syntax-ZLQnfVpK.js">
```

`BlogPost.tsx:14` lazy-loads `CodeBlock` with a comment saying it "only downloads for posts that actually render code blocks" — the manual chunk cancels that.

Homepage JS actually fetched at high priority:

| chunk | raw | gzip |
| --- | ---: | ---: |
| index | 336 kB | 95 kB |
| **syntax** | **634 kB** | **227 kB** |
| vendor | 162 kB | 53 kB |
| motion | 129 kB | 43 kB |
| ui | 72 kB | 25 kB |
| query | 35 kB | 10 kB |
| **total** | | **~452 kB gz** |

Half the homepage's JS payload is a highlighter the homepage never renders. **Fix:** drop the `syntax` entry from `manualChunks` and let Rollup keep it a pure dynamic import.

### 3. The LCP element is animated in from `opacity: 0`

`Hero.tsx:45` animates the `<h1>` with `initial={{opacity:0,y:30}}` … `delay: 0.4, duration: 0.9`. LCP does not count a fully transparent element, so the site's own hero headline pushes LCP out by up to ~1.3 s beyond paint. The hero paragraph (`delay: 0.6`) and CTA row (`delay: 0.9`) compound it.

**Fix:** render the `<h1>` at full opacity immediately; keep entrance animations for below-the-fold sections only.

### 4. ~20 internal links bypass the router

`<a href="/book">` appears in Hero, Navbar (x2), ScrollCTA, Contact, Footer (x9), WhoIWorkWith, Services, ServiceDetail (x2), BlogPost, Checklist. Every click on the primary CTA does a full document reload: re-download, re-parse, re-execute the whole bundle, re-run GA. **Fix:** `<Link to="/book">` (keep real `<a>` only for `/sitemap.xml` and `/rss.xml`).

### 5. Contact form navigates away to Formspree

`Contact.tsx:108` is a plain `action=POST` form. On submit the visitor lands on formspree.io's own confirmation page and is gone. `trackEvent("contact_form_submit")` also fires into an unloading document. **Fix:** `fetch()` the Formspree endpoint with `Accept: application/json`, keep the visitor on-site, show your own success state, then fire the event.

Related: all four lead paths (contact, chatbot lead, chatbot transcript, checklist) POST to the same endpoint `mkgzjlde`, distinguished only by `_subject`/`source`.

## P2 — SEO

### 6. Self-serving `aggregateRating` in JSON-LD

`index.html` ProfessionalService block declares `"ratingValue": "4.9", "reviewCount": "120"` with no `Review` markup and no reviews on the page — the site displays three testimonials. Google's structured-data policy disallows review markup an entity supplies about itself for `LocalBusiness`/`Organization` types; at best it is ignored, at worst it is a structured-data manual action. This is the single riskiest markup on the site.

**Fix:** delete `aggregateRating`, or move the rating to where it is verifiable (link the Upwork profile via `sameAs` and let the testimonials stand on their own with `Review` + named `author`).

### 7. `public/rss.xml` is hand-maintained and stale

It lists 12 posts; `src/data/blogs.ts` has 19. Missing: the seven newest — `laravel-vs-django-for-saas`, `n8n-vs-make-enterprise-automation`, `redis-vs-database-caching-laravel`, `mysql-vs-postgresql-laravel-saas`, `laravel-vs-nodejs-backend-systems`, `asterisk-vs-twilio-cost-breakdown`, `n8n-vs-custom-code-automation`. Those "X vs Y" comparisons are the highest-intent SEO plays on the site, and the feed omits all of them. `lastBuildDate` is frozen at Jul 2026.

**Fix:** extend `scripts/generate-sitemap.ts` to emit `rss.xml` from the same parsed data. One script, two files, no drift.

### 8. Scraped HN content is republished under Usama's byline

`fetch-blogs` scrapes `<p>` text from third-party articles, sets `author: 'Usama Munawar'`, and the posts are merged into `/blog` sorted by date — so freshly scraped HN items sit *above* the hand-written articles. They render at `/blog/<slug>` with full `Article` JSON-LD claiming authorship, and no `rel=canonical` to the source.

Duplicate-content and attribution risk on the one page meant to demonstrate original expertise. **Fix:** either drop the feature, or render trending items as a clearly-labelled link list that goes straight to the source (no `/blog/<slug>` route, no Article schema, no byline).

### 9. Project URLs are numeric

`/project/1` … `/project/11`. No keyword in the URL for eleven case-study pages. Switching to slugs (`/project/solutions-zilla-call-portal`) needs `redirects` in `vercel.json` for the old ids and a sitemap regen — worth doing once, and cheaper now than later.

### 10. Smaller markup issues

- `Index.tsx` offers use bare `"price": "1500"` while the UI says "From $1,500". Use `priceSpecification` with `minPrice` so the markup matches the claim.
- Canonical host is a `*.vercel.app` subdomain. A custom domain would be the single biggest authority upgrade available; the absolute URL is hardcoded in ~8 files, so grep before switching.
- `og-image.jpg` and `og-image.png` both exist; only the PNG (123 kB) is referenced.
- `public/.htaccess` is Apache config with no effect on Vercel.

## P3 — security and correctness

### 11. `supabase/functions/chat` is an unauthenticated, unmetered LLM proxy

`config.toml` sets `verify_jwt = false`, CORS is `*`, and the handler forwards `messages` to the Lovable AI Gateway with no auth, no rate limit, no origin check, no cap on message count or length. Anyone who reads the JS bundle can `curl` it in a loop and spend the `LOVABLE_API_KEY` budget. The client also resends the entire transcript every turn with no trimming, so a single long session grows unbounded.

**Fix:** origin allowlist + a per-IP rate limit + hard caps on `messages.length` and total characters, and reject any client-supplied `role: "system"` message.

### 12. Stored-XSS path via scraped trending posts

`BlogPost.tsx:82,102` inject `renderMarkdown(...)` output through `dangerouslySetInnerHTML` with no escaping. For `blogsData` that content is trusted. For trending posts it is scraped from arbitrary pages: `scrapeContent` strips tags with `/<[^>]*>/g` and named entities with `/&[a-z]+;/gi`, but **numeric** entities (`&#x3C;img src=x onerror=…&#x3E;`) pass through and are decoded by `innerHTML`. Narrow (needs a hostile page on the HN feed plus a visitor opening that auto post) but real, and it disappears entirely if finding #8 is fixed.

### 13. `/auth` has an open public Sign Up tab

`Auth.tsx` exposes registration on a site whose admin area is a read-only stub. Nothing behind it is worth protecting today, but it invites junk accounts and burns Supabase's transactional email quota.

**Fix:** disable signups in Supabase Auth settings and delete the `/auth` + `/admin/*` routes (`AdminDashboard`, `PostEditor`, `Auth`, `useAuth` — `AdminScraper` needs a decision too).

### 14. Stale migrations encode two RLS bugs

Not live (the current Supabase project has no tables), but do not replay them:

- `profiles` UPDATE policy: `USING (auth.uid() = user_id)`, no `WITH CHECK`, no column restriction → a signed-in user can set their own `role = 'admin'` and gain full `blog_posts` CRUD. Roles belong in a separate `user_roles` table that the user cannot write.
- `blog_comments`: `SELECT USING (true)` on a table with a `guest_email` column → anyone with the anon key can dump every commenter's email. Restrict the select to non-PII columns via a view.

### 15. `.env` is committed and not gitignored

It holds only the Supabase anon key (public by design, and duplicated in `client.ts` anyway), so nothing is leaked today. But `.env` is absent from `.gitignore`, so the next secret written there ships to a public repo. Add `.env*` to `.gitignore`, keep `.env.example`.

Related inconsistency: `client.ts` hardcodes the URL while `AIChatbot.tsx:11` reads `import.meta.env.VITE_SUPABASE_URL`. If Vercel's env vars ever diverge from the committed `.env`, the chatbot breaks and the rest of the app doesn't. Pick one source.

### 16. No security headers

Live response carries HSTS (Vercel default) and nothing else — no CSP, `X-Content-Type-Options`, `Referrer-Policy`, or `Permissions-Policy`. Cheap to add in `vercel.json`.

### 17. Comments are theatre

`BlogComments.tsx` stores comments in `useState`, shows "Comment posted!", and loses everything on reload — while collecting the visitor's name and email, which are never sent anywhere. A visitor who leaves a comment and returns finds it gone. **Fix:** remove the component, or wire it to real storage with moderation.
